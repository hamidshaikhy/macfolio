# حساب محلی، رمزگذاری و پشتیبان

## محل داده و کلید

پایگاه `personal-finance-vault-v1` در IndexedDB همان مرورگر ساخته می‌شود. اطلاعات ورود و دفتر مالی به سرور ارسال نمی‌شوند. origin، مرورگر و پروفایل متفاوت فضای جدا دارند؛ وب‌اپ نصب‌شده هم بسته به محیط ممکن است storage مستقل داشته باشد.

شناسه، نام کاربری، salt و شمارهٔ بازبینی فرادادهٔ خوانا هستند. دمو نشانگر نسخهٔ دادهٔ نمونه نیز دارد. نام نمایشی و دفتر مالی در ciphertext قرار می‌گیرند.

| مورد | قرارداد |
| :--- | :--- |
| مشتق‌کردن کلید | PBKDF2-SHA-256، salt تصادفی ۱۶ بایتی، ۳۱۰٬۰۰۰ تکرار |
| رمزگذاری | AES-256-GCM با کلید غیرقابل استخراج Web Crypto |
| IV | ۱۲ بایت تصادفی تازه برای هر ذخیره |
| دادهٔ احراز اصالت | شناسهٔ حساب |
| رمز و کلید بازشده | فقط حافظهٔ نشست؛ در storage ذخیره نمی‌شوند |

پس از رمزگشایی، مدل و ارجاع‌ها بررسی می‌شوند. خروج یا reload نشست بازشده را کنار می‌گذارد.

## چند تب و تغییر رمز

نوشتن بازبینی فعلی storage را با نشست مقایسه می‌کند. ذخیرهٔ تب قدیمی رد می‌شود؛ ورود دوباره آخرین دفتر را باز می‌کند. این کنترل ادغام خودکار ویرایش‌ها نیست.

تغییر رمز salt و کلید را عوض و دفتر را دوباره رمزگذاری می‌کند. نشست قدیمی پس از این تغییر اجازهٔ نوشتن ندارد.

## پشتیبان و انتقال

پشتیبان رمز و salt مستقل دارد و با قرارداد `backup-v1` رمزگذاری می‌شود. نام کاربری و اطلاعات ورود را شامل نمی‌شود. شکل فایل، آرایه‌های بایت و مدل دفتر هنگام بازیابی بررسی می‌شوند.

1. در مبدا، از تنظیمات فایل پشتیبان با رمز مستقل بگیرید.
2. در مقصد حساب محلی بسازید یا وارد حساب خود شوید.
3. فایل را با رمز پشتیبان باز و بازیابی را در حساب فعال انجام دهید.

بازیابی دفتر فعال را جایگزین می‌کند؛ رمز ورود حساب مقصد همان رمز محلی خودش است. پیش از جایگزینی دفتر موجود، پشتیبان آن را نگه دارید. CSV رمزگذاری‌شده نیست.

## مرز حفاظت

این پروژه حفاظت محلی فایل ذخیره‌شده دارد؛ احراز هویت سروری، تأیید ایمیل، اتصال بانکی، همگام‌سازی ابری و بازیابی رمز فراموش‌شده ندارد.

صفحهٔ بازشده، افزونه‌ها و دستگاه باید قابل اعتماد باشند. XSS، افزونهٔ مخرب یا دستگاه آلوده می‌تواند به دفتر بازشده دسترسی پیدا کند. گواهی امنیت بانکی برای پروژه ادعا نشده است. رمز ضعیف نیز در برابر حدس آفلاین روی فایل رمزگذاری‌شده حفاظت محدودی دارد.

پاک‌سازی مرورگر، حالت خصوصی یا سیاست storage ممکن است داده را حذف کند. فایل پشتیبان مستقل برای نگهداری دفتر در دسترس است.

## HTTPS و آفلاین

Web Crypto به secure context نیاز دارد: localhost و HTTPS مناسب‌اند؛ HTTP روی IP شبکهٔ محلی ممکن است مناسب نباشد.

service worker فقط فایل‌های استاتیک همان origin را کش می‌کند. دفتر در IndexedDB رمزگذاری‌شده می‌ماند. نام کش از محتوای build ساخته می‌شود و هنگام فعال‌شدن نسخهٔ جدید، کش‌های قدیمی همین برنامه پاک می‌شوند.
