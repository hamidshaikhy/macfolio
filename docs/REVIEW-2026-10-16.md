# Performance and design review — 2026-10-16

## Implemented

- Initial avatar and Dock icon payload: **3,512,275 → 351,615 bytes**, about 90% less, measured in fresh Chromium production sessions. The avatar is 640px WebP; raster icons are at most 320px with lossless WebP encoding after resizing. Transparency is retained. Original source assets remain recoverable from Git history.
- The bundled **11,897,677-byte** music track is no longer requested at startup. The first Play action starts native HTTP playback directly, preserving the user gesture needed by Safari. The original-byte Blob path remains a fallback for failed native media responses. Existing pause, seek, mute, shared playback and lock controls remain available.
- Project preview cards reuse the existing WebP screenshots and defer image loading; full project galleries retain their original images for enlargement.
- WhatsApp previously used the Telegram-style username in `wa.me`. It now uses the public contact phone in international digits, following the [official click-to-chat format](https://faq.whatsapp.com/5913398998672934). This validates the link format; it does not verify that the phone has a WhatsApp account.
- All **11** images referenced by README were refreshed from the running production build. The gallery count is unchanged. `npm run screenshots:readme` reproduces exactly this set, checks image readiness and reports browser errors.
- PDF tests now cover the current document's actual page count instead of assuming the older two-page résumé. The current supplied résumé renders three pages.

Local measurement details are in ignored `artifacts/integration-measurements/review-before.json` and `review-after.json`. These sample decoded response bodies 2.5 seconds after hero visibility; they are not timings, compressed transfer sizes or a speed benchmark. The initial audio request was still incomplete in the before sample, so its full size is reported separately. Child applications remain absent from the cold page load.

Validation: the production build (including all five child builds), unused-symbol TypeScript check and 44 unit tests passed. Six window/persistence/lazy-load browser scenarios passed across Chromium and WebKit. After correcting the old PDF assumptions and the first-Play WebKit path, all ten final browser checks passed: real decoded audio and controls, all résumé pages/zoom/download, shared project galleries, footer links and the 390×844 phone app flows. The README capture completed all eleven images without browser errors.

## Design proposals for discussion

The design direction stays a familiar desktop containing a more expressive portfolio. Keep the existing sea-green/ink palette, lime action color, portrait reveal, scroll scenes, native window behavior and current mobile layout. The following are proposals, not implemented cosmetic changes:

1. **Separate the five personal apps within the Dock.** Small separators before Barg and after Koja Berim would distinguish the work people can try from general desktop tools, while retaining every app and the current icon choices.
2. **Give live apps a clearer action in portfolio cards.** Place an explicit “Open app” action alongside the case-study action for the five runnable projects. Keep source links quieter. This helps visitors reach the actual work without opening a long case study first.
3. **Reduce competition behind About.** At laptop widths, the initial About window partly covers the widgets. Subtly dimming those background widgets while About is active would make that overlap intentional and keep attention on the portfolio; other apps can keep the regular desktop treatment.

These use existing typography, spacing and colors. No new palette, hero redesign or additional animation is proposed. Screenshots were inspected at 1440px desktop and 390px phone widths. Browser emulation does not replace testing on physical iPhone/iPad Safari.
